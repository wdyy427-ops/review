## 一、修订后的研究问题结构

### RQ1：现有研究如何形成 Perceived Effect 评价证据？

#### RQ1（1）：年代变化趋势

分析以下三类评价证据随发表年代的变化：

1. 五类评价维度 A–E；
2. 五类评价维度下的二级主观指标；
3. 五类测量工具 M1–M5。

#### RQ1（2）：设计情境分布

分析：

1. 评价维度在六类设计领域中的分布；
2. 评价维度在四个设计阶段中的分布。

### RQ2：Perceived Effect 评价证据链的规范性如何？

规范性审查单位由“评价案例”改为“评价证据链”。每条证据链均按照 JCSEE 可操作化标准独立审查。通过规范性门槛的证据链进入 RQ3。

### RQ3：如何根据设计师定义的情境标签推荐评价维度、主观指标和具体工具？

根据设计师选择或输入的评价目的、效果主张、评价对象、设计领域、设计阶段、评价主体、目标用户和可用数据源等标签，分三步推荐：

1. 评价维度；
2. 评价维度下的主观指标；
3. 测量工具类别及具体工具。

同时计算各类输入标签对三个推荐阶段的相对贡献，用于确定网站标签的必选程度、出现顺序和默认折叠方式。

## 二、分析单位及其关系

### 2.1 论文

论文是文献来源单位，用于发表年代、来源、设计领域等文献层变量，以及聚类、抽样和交叉验证分组。

### 2.2 评价案例

评价案例是具有相对独立样本、任务、条件和实施程序的一次评价活动。现有数据中识别出 158 个评价案例。评价目的、对象、情境、参与者和数据源等条件首先在案例层记录。

### 2.3 评价证据链

评价证据链是本研究的核心分析单位：

> Effect Claim / Evaluation Question → Construct → Indicator → Measure

现有数据中有 490 条证据链。RQ1的指标与工具分析、RQ2规范性审查和RQ3建模均以证据链为核心，但统计时必须保留其所属论文和评价案例，以处理同一论文或同一案例内的相关性。

### 2.4 测量工具实例

一条证据链可能使用一种工具，也可能通过问卷与访谈等多种工具形成三角互证。为保持 M1–M5 互斥：

- `chain_id` 保持为评价证据链编号；
- 在证据链下设置 `measure_instance_id`；
- 每个测量工具实例只能归入一个 M 类；
- RQ2仍审查490条父级证据链；
- RQ3的“具体工具推荐”使用工具实例作为分析行；
- 同一证据链使用两种工具时，不强行舍弃其中一种，也不把两种工具合并为一个类别。

这样既保留“490条完整评价实践”，又保证测量工具分类互斥。

## 三、测量工具的五类互斥编码

| 代码 | 最终类别 | 判定标准 |
|---|---|---|
| M1 | 标准化具名量表 | 有正式名称、文献来源和相对固定的题项或计分程序，如 SUS、NASA-TLX、CSI、UEQ |
| M2 | 自编结构化评分工具 | 研究者自行设计 Likert、语义差异、数值等级或专家评分，直接测量某项感知构念 |
| M3 | 定性言语引出工具 | 半结构访谈、深度访谈、焦点小组、开放式回答等，并对文字材料进行质性分析 |
| M4 | 非量表型结构化问卷 | 使用选择、排序、偏好、事实或描述性调查题，但不形成标准化构念得分 |
| M5 | 既有感知资料分析 | 分析研究实施前已经存在的评论、论坛、社交媒体、评价文本或其他二手感知资料 |

### 3.1 互斥判定顺序

1. 数据在本研究实施前已经存在，编码 M5；
2. 新收集的材料以访谈、焦点小组或开放文本形式进行质性分析，编码 M3；
3. 使用有名称、有来源并具有固定计分方式的量表，编码 M1；
4. 使用研究者自编的数值评分直接测量感知构念，编码 M2；
5. 其余新实施的选择、排序、偏好或事实型结构化问卷，编码 M4。

### 3.2 特殊情况

- AHP、感性工学或多准则方法中的自编数值评分，按照实际产生的测量证据编码为 M2；如果只是排序、选择或偏好调查，则编码为 M4。
- 开放式问卷若单独进行主题分析，编码为 M3；若开放题只是结构化问卷的补充说明，不独立形成评价结论，不另建工具实例。
- 纯行为日志、生理指标或模型自动指标不是主观感知测量工具，不进入M1–M5；如果它们与主观证据联合使用，只作为补充数据源编码。
- 纯观察但没有人的感知判断或言语材料，不作为 perceived effect 证据链；思维口述形成言语材料并被质性分析时归 M3。

## 四、RQ1（1）：年代趋势分析方案

### 4.1 年代变量

- 使用论文正式发表年份；
- 在线优先发表与最终出版年份不一致时，以正式引用年份为准；
- 年份缺失的论文不进入年代趋势图，但保留在总体分布中；
- 年度论文量差异很大，因此所有趋势图同时提供“数量”和“年度内部占比”。

仅绘制绝对数量会把文献总量增长误认为某类评价增长，因此不能只报告数量。

### 4.2 评价维度趋势图

**主图：评价维度A–E的年代趋势。**

- 横轴：发表年份；
- 左侧纵轴／面板：每年各维度的证据链数量；
- 右侧纵轴／面板：该维度占当年全部已映射证据链的比例；
- 五条固定颜色折线分别对应A–E；
- 原始年度值使用点和细线；必要时增加三年移动平均作为辅助线，但不能取代原始数据；
- `UNMAPPED` 不并入A–E，单独报告其数量和比例，作为报告不足或编码不确定性的指标。

统计检验：对每个维度检验其年度占比是否呈单调变化。优先采用带年度总证据链数作为分母的二项或准二项趋势模型，并对五次检验进行 BH 多重比较校正。

### 4.3 主观指标趋势图

共形成五幅主图：

1. 图A：A类设计成果质量指标的年代变化；
2. 图B：B类设计过程质量指标的年代变化；
3. 图C：C类设计者认知、情感与能力指标的年代变化；
4. 图D：D类人机交互体验指标的年代变化；
5. 图E：E类社会情境价值指标的年代变化。

每幅图中只出现该评价维度下的二级指标。为避免十余条折线重叠：

- 指标较少时使用多折线图；
- 指标较多时在同一幅图内采用 small multiples，每个指标一个小面板，共用年份和纵轴；
- 每个指标同时报告年度证据链数量和“该指标占当年所属维度证据链的比例”；
- 极低频指标仍保留，不因样本少而删除，但趋势检验标记为“样本不足”。

分母采用当年该维度全部已映射证据链，而不是当年全部证据链。例如C5愉悦的比例应以当年C类证据链为分母。

### 4.4 测量工具趋势图

依据新的M1–M5分类重新编码后绘图：

- 横轴：发表年份；
- 五条线：M1–M5；
- 数量面板：每年各类测量工具实例数；
- 比例面板：各类工具占当年全部主观测量工具实例的比例；
- 同一证据链使用两种工具时计为两个工具实例，但在图注中报告工具实例数与证据链数的区别。

统计检验以工具实例为观测行，以论文为聚类单位，或采用年度聚合比例模型；五类工具的趋势检验进行BH校正。

### 4.5 年代趋势的报告要求

每项趋势均报告：

- 原始数量；
- 年度内部占比；
- 年度斜率及置信区间；
- 校正后的q值；
- 是否存在明显的语料总量影响；
- 低频、年份缺口和自动抽取不确定性。

趋势只解释为“文献评价选择随年代的变化”，不解释为设计实践本身发生了因果变化。

## 五、RQ1（2）：评价维度在设计领域和设计阶段中的分布

### 5.1 设计领域 × 评价维度

使用ICoD六类设计领域和A–E五类评价维度构建6×5列联表。

主图采用带数字标注的热图：

- 单元格文字：该设计领域中对应维度的证据链数；
- 单元格颜色：领域内部行百分比；
- 旁注：涉及该组合的独立论文数和评价案例数。

统计分析包括：

- 卡方检验；
- 稀疏单元格较多时采用Monte Carlo精确检验；
- Cramér’s V及置信区间；
- 标准化残差，用于识别哪些“领域—维度”组合高于或低于随机期望；
- BH校正后的单元格后续检验。

### 5.2 设计阶段 × 评价维度

使用ICoD四个阶段和A–E五类评价维度构建4×5列联表，采用与设计领域相同的图形和统计方法。

### 5.3 重复计算控制

主分析使用证据链，因为研究对象是评价证据选择；同时提供敏感性分析：将同一评价案例内重复出现的相同维度合并为一次。如果链级结果与案例级结果方向不同，正文必须解释同一案例多指标测量造成的影响。

## 六、RQ2：490条评价证据链的JCSEE规范性审查

### 6.1 审查原则

RQ2不再以158个评价案例作为最终质量判定单位。158个案例仅作为证据链的实施情境容器。每条证据链都必须独立回答：

1. 效果主张是否明确；
2. 构念与主张是否对应；
3. 指标是否能够代表构念；
4. 工具是否适合产生该指标；
5. 工具是否具有相应的效度或可信性依据；
6. 数据收集与分析是否足以支持结果；
7. 结果是否真正支持作者的效果主张；
8. 以上判断能否从论文中追溯。

### 6.2 JCSEE操作化条目

| 标准 | 链级审查问题 | 主要证据 |
|---|---|---|
| U5 Relevant Information | 该证据链是否直接回答评价目的和效果主张？ | 研究问题、效果主张、构念与指标对应关系 |
| A2 Valid Information | 指标和工具是否能够支持作者对该构念的解释？ | 工具来源、题项、构念定义、效度、改编与预测试 |
| A3 Reliable Information | 该工具产生的信息是否具有适用的可靠性或可信性证据？ | 内部一致性、评分者一致性、重测；或质性编码一致性、三角互证等 |
| A4 Explicit Program and Context Descriptions | 评价对象、样本、任务和情境是否足以判断适用范围？ | 案例层信息，可继承到各链，但每链单独记录 |
| A6 Sound Designs and Analyses | 与该指标有关的数据设计和分析是否适切？ | 条件设计、比较方式、统计或质性分析 |
| A7 Explicit Evaluation Reasoning | 从测量结果到效果主张的推理是否明确且不过度？ | 结果、效应方向、不确定性和结论 |
| E1 Evaluation Documentation | 该链是否具有可复核的工具、计分、分析、结果和页码记录？ | 工具名称、题项、计分、结果、原文引文和页码 |

### 6.3 不同工具的A2/A3判据

- **M1标准化具名量表：** 检查原始来源、适用构念、版本、改编、计分及当前样本可靠性；仅出现量表名称不足以自动判为充分。
- **M2自编评分：** 检查指标定义、评分标准、题项、内容效度或专家依据、预测试、评分者一致性或内部一致性。
- **M3定性言语引出：** 检查访谈提纲与评价问题的对应、样本合理性、分析方法、编码过程、饱和度、双人编码、成员核查或三角互证。
- **M4非量表型问卷：** 检查问题设计、选项完整性、预测试、排序／选择规则及其与结论的关系；对于事实题，内部一致性可记NA。
- **M5既有资料：** 检查资料来源与目标人群匹配、选择偏差、文本清洗、编码／分类有效性、人工验证及分类器性能。

### 6.4 状态编码

- `S`：论文提供充分、可定位的支持；
- `P`：提供部分支持，但仍存在关键报告缺口；
- `NR`：未报告，不能据此认定做错；
- `C`：发现与规范明显冲突的问题，如工具不测目标构念、结果不能支持主张或存在明显推断越界；
- `NA`：该条标准确实不适用于这种工具或主张，并必须记录理由。

### 6.5 证据链质量层级

以下层级属于本研究的操作化规则，不宣称为JCSEE官方评分。

#### Q1：高可信推荐链

- U5、A2、A6、A7均为S；
- A3为S，或对不适用情形为NA且有理由；
- A4、E1至少为P；
- 不含C。

#### Q2：可用推荐链

- U5、A2、A6、A7、E1至少为P；
- A3为S/P/NA；若为NR，只能进入敏感性分析；
- A4至少为P；
- 不含C。

#### Q3：描述性保留链

- 证据链确实存在，但关键标准为NR，或报告不足以支持工具推荐；
- 仅用于RQ1描述现状，不进入主要推荐模型。

#### 排除链

- 任一核心环节出现C；
- 无法定位效果主张、指标或测量工具；
- 实际不是人的主观感知评价。

### 6.6 RQ2输出

1. 490条证据链逐项审查表；
2. 七项标准的S/P/NR/C/NA分布；
3. 不同工具类别、评价维度、设计领域和年代的规范性差异；
4. Q1、Q2、Q3和排除链数量；
5. 每一项判断对应的PDF页码和短引文；
6. 主审查与宽松敏感性门槛的结果比较。

## 七、RQ3：基于设计师标签定义过程的分层推荐系统

### 7.1 推荐系统输入标签

| 标签组 | 编码内容 | 网站中的作用 |
|---|---|---|
| G1 评价目的 | 四类评价目的 | 限定评价结果将用于什么决策 |
| G2 效果主张／评价问题 | 主张形式、方向及设计师输入的自然语言 | 明确想证明或探索什么效应 |
| G3 评价对象 | 设计成果、过程、AI系统、人机协作、设计者状态、社会后果等 | 明确评价指向什么对象 |
| G4 设计情境 | 六类设计领域、四个设计阶段 | 限定设计工作发生的领域和阶段 |
| G5 相关人的价值 | 评价主体和目标用户 | 明确谁作出判断、评价服务于谁 |
| G6 可信证据可行条件 | 可用数据源及可接触的评价者 | 约束实际能够采用的方法和工具 |
| G7 AI活动特征 | AI功能、AI角色和具体设计任务 | 只有在具有增量解释力时进入正式网站 |

### 7.2 防止目标泄漏

当模型预测“评价维度”或“主观指标”时，输入中不能直接包含已经人工编码好的评价维度或指标名称，否则模型只是重复答案。

效果主张采用两种方式处理：

1. 用描述性／比较性／因果性／探索性等“主张形式”作为结构化标签；
2. 自然语言效果主张只用于语义检索和候选解释，不直接用于计算标签组权重，除非经过严格的论文分组交叉验证和去除显式指标词实验。

### 7.3 三阶段输出

#### 阶段一：推荐评价维度

输入G1–G7，输出A–E的概率、支持链数、支持论文数和质量层级。允许Top-3推荐，因为同一情境可能合理地对应多个维度。

#### 阶段二：推荐主观指标

在设计师确认某一评价维度后，只在该维度的二级指标中排序。输出：

- 指标名称；
- 与当前标签组合的匹配概率；
- 支持论文与证据链；
- 适用边界；
- 常见遗漏指标。

#### 阶段三：推荐测量工具

在维度和指标确定后，推荐：

1. M1–M5工具类别；
2. 具体具名量表、题项方案、访谈方案或资料来源；
3. 工具的适用条件、报告完整性和证据质量；
4. 原文出处及页码。

具体工具名称通常是长尾类别，不能仅依赖多分类模型。应采用“模型推荐工具类别＋证据检索排序具体工具”的组合方案。

### 7.4 标签组权重的计算

权重分别针对三个预测目标计算，不能用一套权重同时解释维度、指标和工具：

- `W_dimension(G)`：标签组对评价维度推荐的贡献；
- `W_indicator(G | dimension)`：在维度确定后，对指标推荐的贡献；
- `W_tool(G | dimension, indicator)`：在维度与指标确定后，对工具推荐的贡献。

#### 主要权重方法：分组消融重要性

1. 建立包含全部标签组的完整模型；
2. 每次删除一个标签组重新训练；
3. 计算删除后交叉验证Macro-F1或对数损失下降量；
4. 将各组下降量归一化为0–100%的相对权重：

\[
W_g = \frac{\max(0,\Delta_g)}{\sum_j \max(0,\Delta_j)}
\]

5. 以论文为重抽样单位进行bootstrap，报告95%置信区间。

这一权重直接回答：“如果网站不询问这类标签，推荐准确性会下降多少？”

#### 交叉验证方法

- 正则化多项逻辑回归：提供可解释的线性基线；
- 平滑条件频率／经验贝叶斯模型：处理稀疏组合并形成透明推荐；
- CatBoost或同类类别模型：检验非线性交互；
- 分组置换重要性：验证消融结果；
- Cramér’s V、条件概率、Lift和互信息：作为描述性关联证据。

所有预测模型均使用按论文分组的交叉验证，确保同一论文的证据链不会同时进入训练集和测试集。

### 7.5 网站标签顺序的确定

标签界面不能凭主观判断排序。完成建模后：

1. 对三个推荐阶段分别计算标签组权重；
2. 权重高且用户能够回答的标签设置为必选；
3. 权重中等的标签设置为推荐填写；
4. 权重低、置信区间跨零或没有增量价值的标签折叠为可选；
5. 如果某标签只影响工具、不影响维度，则在工具推荐阶段再询问，避免增加前期负担。

网站同时显示全局权重和当前一次推荐的局部贡献，避免把全局规律误解为每个个案都相同。

### 7.6 稀疏组合与回退规则

当设计师选择的标签组合没有足够证据时：

1. 首先使用完全匹配组合；
2. 支持论文不足时，按标签权重从低到高逐项放宽；
3. 使用经验贝叶斯平滑，避免一两篇论文产生100%推荐概率；
4. 低于最低支持门槛时显示“研究空白／证据不足”，而不是强行推荐；
5. 每条推荐显示支持论文数、证据链数、规范性等级和被放宽的标签。

## 十、需要在审查时重点确认的内容

1. RQ1趋势图是否同时接受“数量＋年度内部比例”；
2. 490条父级证据链下设置工具实例子表是否符合研究表述；
3. RQ2是否采用Q1高可信、Q2可用、Q3描述性三个层级；
4. A3未报告的链是否只进入敏感性分析，不进入主要推荐模型；
5. RQ3是否接受“效果主张由设计师输入，系统推荐维度、指标和工具”，而不是由系统替设计师生成效果主张；
6. 标签组权重是否采用按论文分组交叉验证下的消融重要性作为主结果。
